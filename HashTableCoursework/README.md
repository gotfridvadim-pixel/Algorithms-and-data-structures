# Хеш-таблица с методом цепочек

Учебная реализация хеш-таблицы на Python. Коллизии разрешаются методом цепочек: элементы, получившие одинаковый индекс корзины, сохраняются в односвязном списке.

Реализация поддерживает:

- добавление, получение, изменение и удаление элементов;
- проверку наличия ключа;
- перебор ключей и пар `(ключ, значение)`;
- пользовательские хеш-функции;
- автоматическое увеличение количества корзин;
- просмотр внутреннего содержимого корзин.

## Быстрый старт

```python
from hash_table import HashTable

table = HashTable()

table.insert("name", "Ivan")
table["age"] = 20

print(table["name"])        # Ivan
print(table.search("age"))  # 20
print("name" in table)      # True
print(len(table))           # 2

for key, value in table.items():
    print(key, value)
```

Запуск демонстрационного файла:

```bash
python main.py
```

## Создание таблицы

```python
from hash_functions import additive_hash
from hash_table import HashTable

table = HashTable(capacity=8, hash_func=additive_hash)
```

Параметры конструктора:

| Параметр | Значение по умолчанию | Описание |
|---|---:|---|
| `capacity` | `8` | Начальное количество корзин |
| `hash_func` | `additive_hash` | Функция, возвращающая целочисленный хеш ключа |

`capacity` должна быть положительным целым числом. Значения `0` и отрицательные числа вызывают `ValueError`, а значения другого типа, включая `bool`, — `TypeError`.

Хеш-функция по умолчанию принимает только строки. Для ключей других типов необходимо передать собственную функцию.

## Операции

### Добавление через `insert`

```python
table.insert("name", "Ivan")
```

`insert(key, value)` добавляет новую пару. Если такой ключ уже существует, возникает `KeyError`, а старое значение сохраняется.

```python
table.insert("name", "Ivan")
table.insert("name", "Petr")  # KeyError
```

### Добавление и изменение через `[]`

```python
table["city"] = "Moscow"  # новый элемент
table["city"] = "Kazan"   # изменение существующего элемента
```

Оператор присваивания добавляет отсутствующий ключ или изменяет значение существующего ключа. При изменении количество элементов не увеличивается.

### Получение значения

Получение через квадратные скобки соответствует поведению стандартного словаря:

```python
print(table["city"])
print(table["missing"])  # KeyError
```

Метод `search` вместо исключения возвращает `None`, если ключ отсутствует:

```python
value = table.search("city")     # сохранённое значение
value = table.search("missing")  # None
```

Если в таблице хранится значение `None`, по результату `search` нельзя определить, существует ли ключ. Для однозначной проверки следует использовать оператор `in`.

### Проверка наличия ключа

```python
if "city" in table:
    print("Ключ найден")

if "country" not in table:
    print("Ключ отсутствует")
```

### Удаление

```python
table.delete("city")
```

Если ключ существует, соответствующий узел удаляется, а размер таблицы уменьшается на единицу. Удаление отсутствующего ключа ничего не делает и не вызывает исключение.

### Размер таблицы

```python
print(len(table))
```

`len(table)` возвращает количество сохранённых пар, а не количество корзин.

### Перебор ключей

```python
for key in table:
    print(key, table[key])
```

Порядок обхода зависит от индексов корзин и расположения элементов в цепочках. Он не является порядком добавления и может измениться после рехеширования.

### Перебор пар

Метод `items()` возвращает генератор пар `(key, value)`:

```python
for key, value in table.items():
    print(key, value)

pairs = list(table.items())
```

### Просмотр корзин

`get_view()` предназначен для демонстрации и отладки внутреннего устройства таблицы. Он возвращает список корзин: каждая корзина представлена списком пар `(key, value)`, а пустая корзина — пустым списком `[]`. Индекс корзины соответствует её позиции во внешнем списке.

```python
for index, bucket in enumerate(table.get_view()):
    print(f"Корзина {index}: {bucket}")
```

Результат можно сохранить, многократно обходить и получать корзины по индексу:

```python
view = table.get_view()
print(view[0])   # содержимое первой корзины
print(len(view)) # текущее количество корзин
```

При вызове создаются новые списки и кортежи пар. Последующие добавления и удаления элементов таблицы не обновляют сохранённый результат. При этом сами объекты ключей и значений не копируются: изменения внутри изменяемого значения, например списка, будут видны и через результат `get_view()`.

## Краткий справочник API

| Операция | Назначение | Поведение при отсутствии ключа |
|---|---|---|
| `table.insert(key, value)` | Добавить новую пару | Добавляет элемент |
| `table[key] = value` | Добавить или изменить пару | Добавляет элемент |
| `table[key]` | Получить значение | `KeyError` |
| `table.search(key)` | Найти значение | Возвращает `None` |
| `key in table` | Проверить наличие ключа | Возвращает `False` |
| `table.delete(key)` | Удалить пару | Ничего не делает |
| `len(table)` | Получить количество элементов | — |
| `iter(table)` | Перебрать ключи | — |
| `table.items()` | Перебрать пары | — |
| `table.get_view()` | Получить список корзин со списками пар | — |

## Хеш-функции

В модуле `hash_functions.py` определены две функции.

### `additive_hash`

Аддитивный хеш равен сумме кодов символов строки:

```python
from hash_functions import additive_hash

print(additive_hash("abc"))  # 294
```

Функция проста, но не учитывает порядок символов: строки `"abc"` и `"cba"` имеют одинаковый хеш.

### `polynomial_hash`

Полиномиальный хеш вычисляется с основанием 31 и учитывает порядок символов:

```python
from hash_functions import polynomial_hash
from hash_table import HashTable

table = HashTable(hash_func=polynomial_hash)
table["abc"] = 1
```

Обе встроенные хеш-функции принимают только строки и вызывают `TypeError` для ключей других типов.

## Пользовательская хеш-функция

Хеш-функция должна принимать ключ и возвращать целое число. Итоговый индекс вычисляется по формуле:

```text
index = hash_func(key) % capacity
```

Пример таблицы с целочисленными и строковыми ключами:

```python
from hash_functions import additive_hash
from hash_table import HashTable


def mixed_hash(key):
    if isinstance(key, int):
        return key
    if isinstance(key, str):
        return additive_hash(key)
    raise TypeError(f"Неподдерживаемый тип ключа: {type(key).__name__}")


table = HashTable(hash_func=mixed_hash)
table[10] = "integer"
table["10"] = "string"
```

## Коллизии

Коллизия возникает, когда разные ключи получают один индекс корзины. В этой реализации элементы одной корзины объединяются в односвязную цепочку.

```python
from hash_table import HashTable


def constant_hash(key):
    return 0


table = HashTable(capacity=4, hash_func=constant_hash)
table["first"] = 1
table["second"] = 2
table["third"] = 3

assert table["first"] == 1
assert table["second"] == 2
assert table["third"] == 3
```

Все три элемента находятся в корзине с индексом `0`, но различаются сравнением ключей внутри цепочки.

## Рехеширование

Коэффициент загрузки вычисляется перед добавлением нового элемента:

```text
alpha = size / capacity
```

Если `alpha >= 1`, количество корзин удваивается. Все существующие элементы заново распределяются по корзинам, потому что их индексы зависят от новой вместимости.

Например, при начальной вместимости `2` расширение до `4` выполняется перед добавлением третьего элемента:

```python
table = HashTable(capacity=2)
table["a"] = 1
table["b"] = 2
table["c"] = 3  # перед добавлением вместимость увеличится до 4
```

Таблица автоматически увеличивается, но не уменьшается после удаления элементов.

## Сложность операций

| Операция | В среднем | В худшем случае |
|---|---:|---:|
| Добавление | `O(1)` | `O(n)` |
| Поиск | `O(1)` | `O(n)` |
| Изменение | `O(1)` | `O(n)` |
| Удаление | `O(1)` | `O(n)` |
| Рехеширование | — | `O(n)` |
| Полный обход | `O(n + m)` | `O(n + m)` |

Здесь `n` — количество элементов, а `m` — количество корзин. Худший случай возникает, когда много ключей попадают в одну цепочку.

## Ограничения

- Хеш-таблица не сохраняет порядок добавления элементов.
- Встроенные хеш-функции поддерживают только строковые ключи.
- Корректность пользовательской хеш-функции не проверяется заранее.
- Таблица не уменьшается автоматически.
- Реализация не предназначена для одновременного изменения из нескольких потоков.
- Не следует изменять таблицу во время перебора её ключей или пар через `items()`.
